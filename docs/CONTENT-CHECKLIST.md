# 内容清单 · 需要基金会提供的材料

> 这份清单对应站内所有黄色标记（`TODO_FOUNDATION_INPUT`）的位置。
> 全部填完之前，`pnpm build` 会主动失败，防止占位内容误上线。

## 为什么这件事比一般网站严格

普通商业网站上的示例文案是"待优化"，慈善机构官网上的编造内容是**行政违法**。

《中华人民共和国慈善法》第 111 条：以虚假宣传、虚构事实等方式欺骗、诱导募捐对象实施捐赠的，责令停止募捐活动、退还违法募集的财产；不能退还的予以没收；**情节严重的吊销登记证书，被吊销公开募捐资格证书的五年内不得再次申请**。

所以本项目把内容分成两类，在代码里就分开：

| 标记 | 含义 | 谁来写 | 是否阻塞上线 |
|---|---|---|---|
| `TODO_FOUNDATION_INPUT` | **事实性内容** —— 数字、资质、人名、项目、日期、金额、合作方 | 只能由基金会提供 | **是**，构建直接失败 |
| `DRAFT` | **表述性文案** —— 口号、栏目引导语、说明文字 | 我已起草，你审阅修改 | 否 |

站内运行时也能一眼分辨：黄色高亮块 = 必填事实，虚线下划线 = 待审阅文案。

## 一、机构法定信息（最高优先级）

这些出现在页脚、结构化数据和多个页面，缺一项整站都不完整。对应文件：`content/site.ts`。

- [ ] **统一社会信用代码**（18 位）
- [ ] **登记管理机关** —— 例：北京市民政局
- [ ] **成立日期**（YYYY-MM-DD）
- [ ] **业务主管单位** —— 如无填「无」
- [ ] **「慈善中国」主体公示页 URL** —— 在 <https://cszg.mca.gov.cn> 搜索本机构后复制页面地址。这是**最强的信任信号**，比任何设计都有效
- [ ] **办公地址、邮编、电话、邮箱**
- [ ] **投诉举报电话与邮箱** —— 国内基金会官网的惯例栏目
- [ ] **审计机构名称**
- [ ] **公益性捐赠税前扣除资格**的年度与文号（如未取得，填「暂未取得」）
- [ ] **官方账号** —— 微信公众号、微博等

### 需要你确认的一个关键问题

**基金会是否已取得《慈善组织公开募捐资格证书》？**

这是决定整站信息架构的唯一分叉点，也是本项目唯一需要你明确答复才能定稿的事：

- **没有**（新设立的基金会大概率如此）：当前站点已按这个前提搭好 —— 一级导航里没有捐赠入口，页脚有「本会目前不具有公开募捐资格」的显式声明。依《慈善法》第 22 条，依法登记满一年方可申请该资格；在取得之前，官网上任何面向不特定公众的捐赠入口都可能被认定为违法公开募捐，可处警告、责令停止、责令退还，情节严重罚款 2 万至 20 万元。
- **已有**：把 `content/site.ts` 里的 `features.hasPublicFundraising` 改成 `true`，导航和首页 CTA 会自动切换到公募范式。另需提供公开募捐资格证书编号与募捐方案备案编号。

> 即使有资格，也**不建议在官网自建微信/支付宝收款**。《慈善法》第 23 条要求互联网公开募捐信息在民政部指定平台发布，官网只能「同时」发布；2026-05-01 施行的新规进一步明确平台不得代收捐赠财产。正确做法是官网做项目介绍与信任信号，「立即捐赠」外链到腾讯公益、支付宝公益等指定平台上的对应项目页。

## 四、信息公开的法定时限

《慈善组织信息公开办法》（民政部令第 81 号）**2025-10-01 公布、2026-01-01 起施行**，2018 年版（第 61 号令）同时废止。站点的信息公开栏目是按新版建的。

| 公开事项 | 时限 | 对应页面 |
|---|---|---|
| 章程、决策机构成员、下设机构、重要关联方、联系方式及官方账号、内部制度 | 信息形成起 **30 日内** | `/disclosure/charter`、`/about/council` |
| 年度工作报告 + 财务会计报告 | 每年 **5 月 31 日前** | `/disclosure/annual-report`、`/disclosure/financial` |
| 慈善项目：名称、内容、时间、地域、受益群体、收支、第三方执行情况 | 结束后 **3 个月内**；周期超 6 个月的至少每 **3 个月**一次 | `/disclosure/projects` |
| 上年度重大慈善项目实施情况（**不具公募资格的组织也须公开**，第 81 号令新增） | 每年 **5 月 31 日前** | `/disclosure/projects` |
| 项目终止后剩余捐赠财产处理 | 终止后 **3 个月内** | `/disclosure/projects` |
| 与重要关联方的捐赠、资助、投资、交易 | 发生后 **30 日内** | `/disclosure/related-party` |
| 慈善信托名称、受托人、委托金额（如有） | 设立后 **30 日内** | 需新建 `/disclosure/trust` |
| 负责人薪酬前五位与经费标准（**仅公募组织**） | 年度 | 需新建 `/disclosure/compensation` |

两条要点：

1. **统一平台优先。** 第 3 条要求慈善组织在其他渠道公布的信息，必须与国务院民政部门建立的统一平台（「慈善中国」）一致。官网的信息公开栏目本质是平台数据的镜像，不是自由创作区。站内每个信息公开页顶部都已加上这句声明。
2. **隐私红线。** 第 21 条：捐赠人、志愿者、受益人**不同意公开**的姓名、住所、通讯方式不得公开。「爱心榜」和「受益人故事」恰恰是转化力最强、隐私风险也最高的两个板块。

## 五、影像

首页目前用纯 CSS 的暖阳光晕作主视觉，没有使用任何照片。这是有意的：

- **不使用 AI 生成的「受益人」「项目现场」类图片。** 除了《人工智能生成合成内容标识办法》（2025-09-01 施行）要求此类内容同时具备显式与隐式标识之外，更实际的原因是：一旦被识破，对公益机构公信力的打击是毁灭性的，且极易被解读为虚构项目现场。
- **不使用图库摆拍。** 同理，那是另一种形式的失真。

需要你提供：

- [ ] **项目现场 / 服务对象的真实照片**，附拍摄时间、地点、说明
- [ ] **每张涉及人物的照片的书面公开授权**；涉及未成年人的另需监护人同意
- [ ] **机构 logo 源文件**（SVG 优先）—— 当前站内用的是临时几何标识（`src/components/brand-mark.tsx`），拿到正式 VI 后替换这一个文件即可，站内所有引用点会同步更新

如果暂时没有合规影像，当前的纯光晕方案可以长期使用，视觉上完全成立。

## 六、需要专业意见的两项

这两项我不建议由 AI 起草，也不建议照抄模板：

1. **隐私政策。** 《网络数据安全管理条例》（国务院令第 790 号，2025-01-01 施行）要求处理医疗健康、金融账户等敏感个人信息取得**单独同意** —— 受益人健康信息与捐赠人支付信息都落在这个范围，通用模板覆盖不到。
2. **公开募捐相关的所有表述。** 涉及资格、备案编号、募捐方案的措辞，建议由法务或登记管理机关确认。
